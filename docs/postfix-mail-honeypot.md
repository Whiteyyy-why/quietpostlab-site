# 用 Postfix 搭建一个只收信的垃圾邮件蜜罐

我们已经找过不少开源垃圾邮件语料，想再补充一些近期的真实来信。为此，我们用一台 Ubuntu 24.04 LTS 云服务器部署 Postfix，接收投向专用子域的邮件，并保存原始样本。这篇记录从 DNS 配置到第一封测试邮件落盘的过程。

## 让外部邮件服务器找到收件主机

先分配一个独立的收件子域 `trap.quietpostlab.me`。给它添加一条优先级为 10 的 MX 记录，指向 `mx.trap.quietpostlab.me`，再给邮件主机名添加 A 记录，指向云服务器的公网 IPv4 地址。

外部邮件服务器按 **MX → A → TCP 25** 的顺序找到收件服务。部署时分别检查云安全组的入站 TCP 25 规则和 Postfix 的本机监听状态，最后从另一台机器验证公网连接。网页用自己的域名和托管平台，迁移网页时邮件仍走同一条投递链路。

## 用 Postfix 保存原始邮件

安装 Postfix 后，把实验子域设为虚拟邮箱域。符合地址规则的收件人都映射到同一个 Maildir，可以给每个公开渠道分配不同的地址。每封来信占一个文件，邮件头、正文和附件都随原始邮件保存。归档由专用服务账号管理。

这台服务器只接收投向实验子域的邮件。Postfix 会拒绝第三方域的中继请求，SMTP 登录和对外投递均已禁用。单封上限为 20 MiB，同时限制连接数和 SMTP 超时，并为日志设置轮转。队列磁盘空间不足时，服务会暂缓接收。

## 从公网投递，确认邮件落盘

服务器上先检查配置、端口和队列。

```bash
sudo postfix check
sudo ss -lnt '( sport = :25 )'
sudo postqueue -p
```

随后从公网向实验子域发了两封带标记的测试邮件，一次直连公网 IP，一次用邮件主机名。两封均成功归档，中文主题、纯文本正文、HTML 和附件都能完整读取。重启 Postfix 后，已有邮件仍在。向域外收件人发起的投递请求也按预期被拒绝。

这一步验证了收件链路。收集效果还要看公开后的真实来信。
